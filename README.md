# Daniel A. Arnett — авторский архив

Главная страница, библиотека и серверное ядро для публикации прозы. Python 3.12+, Flask, SQLAlchemy, Jinja, SQLite / PostgreSQL. Основные шрифты — локальные Literata и Golos Text; читательская страница использует существующий `reading.css`.

## Текущее состояние

- `index.html` — статический макет для GitHub Pages. Черновики → об авторе → книги → процесс работы → читательский круг. Три равные карточки с общей рамкой, кликабельными артом и названием; `art1.png` / `art2.png` меняются при наведении и фокусе с клавиатуры. `author.png` — портрет, `arrow.png` — единая стрелка. Для «Мелков» временно оставлен номер, для первого черновика пока один арт.
- Flask-версия главной находится в `app/templates/home.html`. Она открывает опубликованную первую главу прямо из карточки; если текста ещё нет, открывает страницу произведения с соответствующим сообщением.
- `/library`, `/works/<slug>`, `/read/<work_slug>/<chapter_slug>` — опубликованные произведения, оглавление и чтение. Место чтения сохраняется локально, а после входа — также в БД.
- `/admin` — создание и редактирование произведений и глав, порядок, публикация, режим доступа, отдельный бесплатный фрагмент, основной и сменный арт. Вкладка читателей позволяет сбросить кэш проверки доступа.
- Boosty и проверка группы **отключены по умолчанию**. Бесплатное чтение и авторская панель работают без подписки. Код входа Telegram и проверки членства подготовлен и проверяется тестами с имитацией провайдера; реальное подключение ещё предстоит.

GitHub Pages показывает главную и открытый пролог «Моя слабость, моя боль»: `/read/moya-slabost-moya-bol/prolog/`. Арт и название первой карточки ведут прямо к тексту. Эта бесплатная глава опубликована отдельной HTML-страницей по просьбе автора; закрытые тексты, БД и ключи в Git не входят. Python на Pages не выполняется, поэтому авторская панель и проверка подписки заработают публично после переноса приложения на хостинг.

Обновить публичный пролог после редактирования в БД: `flask --app run export-free-chapter moya-slabost-moya-bol prolog`, затем закоммитить страницу. Команда экспортирует только явно выбранную, опубликованную и полностью бесплатную главу; скрытые главы, закрытые произведения и режим фрагмента отвергаются до выборки полного текста. Превращение уже опубликованной бесплатной главы в закрытую потребует отдельно убрать её публичную копию; опубликованный ранее текст нельзя сделать секретным задним числом.

## Локальный запуск (PowerShell)

Из каталога проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\flask --app run db upgrade
.\.venv\Scripts\flask --app run seed-catalog
.\.venv\Scripts\waitress-serve --listen=127.0.0.1:5000 run:app
```

Открыть <http://127.0.0.1:5000/>. `.env` копируется при первой настройке; существующий файл с настройками заменять не нужно. В development случайный секрет сессий автоматически сохраняется в `instance/development-secret`. SQLite находится в `instance/library.sqlite`.

Каталог заполняется названиями и обложками, без выдуманных глав и текста. Повторный `seed-catalog` не перезаписывает изменения автора. У трёх черновиков в БД установлена готовность 50%; на новой галерее эти подписи не показываются.

### Импорт «Моей слабости, моей боли»

```powershell
.\.venv\Scripts\flask --app run import-docx "D:\Downloads\2_5294239618357567965.docx" --publish
```

Это импорт конкретной структуры документа: название, подзаголовок, посвящение, заголовок «Пролог», литературные абзацы. Слова и авторская пунктуация не редактируются; курсив и полужирные выделения сохраняются. Таблицы, изображения, непринятые правки и сноски требуют отдельного переноса и не пропускаются молча. Повторная замена существующего пролога требует явного `--replace`. Без `--publish` глава остаётся скрытой.

После импорта: <http://127.0.0.1:5000/read/moya-slabost-moya-bol/prolog>.

### Вход владельца без Telegram

В другом терминале:

```powershell
.\.venv\Scripts\flask --app run create-admin --local
```

Команда выдаёт одноразовую ссылку на 10 минут. Откройте её и нажмите кнопку входа. Она работает только на localhost в development; в production маршрут отключён. Права владельца выдаются командой на сервере, а не полем из браузера. Ссылку входа не нужно сохранять в репозитории.

В авторской панели сначала создаётся произведение, затем его главы. Для показа текста нужны обе отметки: видимое произведение и опубликованная глава. Уникальные адреса задаются латиницей, например `goryachee-solntse` и `glava-1`. Арты берутся из `/images/имя-файла.png`; поле второго арта необязательно. Изменение галереи на сервере выполняется через эти поля. Статический `index.html` обновляется отдельно до переезда на хостинг.

## Правила доступа

| Настройка главы | Анонимный читатель | Подтверждённый участник группы / владелец |
| --- | --- | --- |
| `free` | Полный текст | Полный текст |
| `fragment` | Только отдельное поле фрагмента | Полный текст |
| `subscriber` | Сообщение о доступе, HTTP 403 | Полный текст |

`Work.access_type=subscriber` закрывает все главы произведения, включая главы с собственной отметкой `free`. Для остальных произведений доступ определяется каждой главой. Скрытые и будущие публикации возвращают 404, в том числе владельцу на читательском маршруте; владелец редактирует их в панели.

Проверка `can_read` выполняется **до выборки текста**. Полный текст и фрагмент — отдельные отложенные столбцы; страницы каталога не загружают их. HTML очищается белым списком, включая текст после преобразования Markdown. Публичного API выдачи прозы нет. Сервер раздаёт только разрешённые каталоги изображений, CSS и шрифтов, собственную статику и два ресурса читательского оформления. Корень репозитория, БД и `private_content` не раздаются.

При выключенных подписках закрытый текст доступен только владельцу. Включение подписок не означает подключения оплаты: приложение не принимает платежи и не обращается к неофициальным API Boosty.

## Будущее подключение Telegram / Boosty

После создания страницы Boosty и закрытой группы:

1. Настроить управление участниками группы средствами выбранной связки Boosty. Приложение проверяет членство, но само не подтверждает оплату и не добавляет участников.
2. Создать приложение входа в настройках Telegram-бота, указать домен и точный callback `https://ваш-домен/auth/callback`. Получить `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET`.
3. Назначить бота администратором закрытой группы. Записать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_SUBSCRIBERS_CHAT_ID` в приватную среду сервера.
4. Назначить владельца: `flask --app run create-admin --telegram-id ВАШ_ЧИСЛОВОЙ_ID`.
5. Проверить настоящий вход, участника, отсутствие членства и отзыв доступа. Только затем установить `SUBSCRIPTIONS_ENABLED=1` и `BOOSTY_URL=https://boosty.to/имя`.

Используется официальный Telegram OpenID Connect: Authlib проверяет подпись ID token, issuer, audience, срок действия, state и nonce; обмен кода использует PKCE S256. Для Bot API берётся подписанное числовое поле `id`, а не OIDC `sub` и не username. Результат `getChatMember` кэшируется до 300 секунд с привязкой к группе и боту. `member`, `administrator`, `creator` дают доступ; другие состояния — нет. После истечения кэша ошибка Telegram не продлевает старый положительный результат. Отзыв членства может отражаться с задержкой до срока кэша; владелец может сбросить его вручную.

Основания реализации: [Telegram Login](https://core.telegram.org/bots/telegram-login), [getChatMember](https://core.telegram.org/bots/api#getchatmember), [Authlib Flask OAuth client](https://docs.authlib.org/en/latest/oauth2/client/web/flask.html).

## Перенос на хостинг

Нужен хостинг с Python/WSGI, HTTPS, постоянной БД и Redis. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) предназначен для статических файлов. На обычном Linux-хостинге команды аналогичны локальным, пути исполняемых файлов — `.venv/bin/…`.

1. Установить зависимости, создать приватную `.env` вне публичной раздачи. Для production задать:

   ```dotenv
   APP_ENV=production
   SECRET_KEY=<случайный секрет минимум 32 символа>
   PUBLIC_BASE_URL=https://ваш-домен
   TRUSTED_HOSTS=ваш-домен
   RATELIMIT_STORAGE_URI=redis://127.0.0.1:6379/0
   DATABASE_URL=sqlite:///library.sqlite
   TRUST_PROXY=1
   SUBSCRIPTIONS_ENABLED=0
   ```

   Секрет можно создать командой `python -c "import secrets; print(secrets.token_hex(32))"`. Для PostgreSQL вместо SQLite: `DATABASE_URL=postgresql://user:password@host/database`; драйвер psycopg уже включён. Спецсимволы пароля должны быть URL-encoded. Секреты не записываются в Git и скриншоты.

2. Выполнить `flask --app run db upgrade`, затем `seed-catalog`. Приватно перенести DOCX и импортировать его или восстановить приватную резервную копию БД. Клонирование Git само по себе не переносит рукописи и пользователей.
3. Запустить `waitress-serve --listen=127.0.0.1:5000 run:app` под менеджером процессов. Перед ним настроить один доверенный HTTPS reverse proxy. `TRUST_PROXY=1` допустим только при такой схеме; WSGI-порт не должен быть доступен извне. При прямом HTTPS WSGI-подключении оставить `TRUST_PROXY=0`.
4. Проксировать маршруты приложения. Не делать весь каталог проекта корнем публичного файлового сервера; не кэшировать HTML `/read`, `/admin`, `/auth`, `/api`. Ответы приложения содержат `private, no-store` и `Vary: Cookie`.
5. Настроить резервные копии БД и приватных ключей отдельно от Git. Для SQLite копировать остановленную БД либо использовать SQLite Backup API; для PostgreSQL — штатный `pg_dump`. Миграции выполнять после резервной копии. Проверить восстановление на отдельной БД.
6. Запускать `flask --app run prune-audit` ежедневно через расписание хостинга. По умолчанию удаляются журналы чтения старше 7 дней и просроченные локальные ссылки входа. Приложение само не создаёт расписание.

Production отказывается стартовать без секрета, HTTPS-адреса и общего хранилища ограничений запросов. Debug выключен. Cookies: Secure, HttpOnly, SameSite=Lax; POST защищены CSRF. Включены CSP и другие защитные заголовки. Настройки и проксирование сверяются с [документацией безопасности Flask](https://flask.palletsprojects.com/en/stable/web-security/) и [развёртывания Flask](https://flask.palletsprojects.com/en/stable/deploying/).

## Ограничения массового скачивания и метки

На чтение действует лимит на пользователя/IP по всем главам, дополнительный лимит по IP и общий лимит приложения. Прогресс чтения ограничен отдельно. Redis обязателен в production, чтобы лимиты были общими для процессов. Журнал чтения содержит пользователя, главу, время, код ответа, User-Agent и HMAC IP-адреса; сырой IP и токены в журнал БД не сохраняются. Логи reverse proxy настраиваются отдельно, без токенов авторизации и query string callback.

Закрытые полные тексты могут получать случайную метку выдачи, подписанную HMAC, и последовательность невидимых символов. Она сопоставляется с пользователем только на сервере; Telegram ID в HTML не вставляется. Для разбора найденной копии: `flask --app run trace-receipt путь-к-копии.txt`. Метка и ограничения выделения/копирования — дополнительное препятствие, а не защита от снимка экрана, OCR или мотивированного копирования. Невидимую метку можно удалить. Отредактированный текст без сохранившейся метки установить по пользователю нельзя. `FINGERPRINT_ENABLED=0` отключает метки.

## Проверки и устройство проекта

```powershell
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\flask --app run db check
```

Тесты используют временные БД и вымышленные тексты. Проверяются режимы доступа, отсутствие запроса закрытого тела до проверки прав, истечение кэша и сбой Telegram, реальная валидация тестовых подписанных OIDC-токенов, поддельные cookies/ID, CSRF, XSS, изоляция прогресса, лимиты запросов, импорт и метки. Реальные ключи Telegram, Boosty и рукопись для тестов не нужны. GitHub Actions выполняет тесты и проверяет миграции с пустой БД.

- `app/auth`, `app/library`, `app/admin` — маршруты.
- `app/services/access.py` — единая проверка доступа.
- `app/services/content.py` — очистка HTML и нумерация абзацев.
- `app/services/docx_import.py` — импорт предоставленного типа DOCX.
- `js/reader.js` — общие для Pages и Flask закладка и показатель чтения; `css/site.css` и `js/site.js` — общий интерфейс этих страниц.
- `migrations` — последовательные изменения схемы БД.
- `css/home.css`, `css/fonts.css`, `images`, `fonts` — общий внешний вид.
- `js/home.js` и `app/static/home.js` — одинаковые обработчики макета и серверной главной; обновлять вместе.
- `reading.html`, `index-previous.html`, `plans.html` — прежние статические страницы; Flask не раздаёт их как источник актуальной прозы.

Визуальное направление и происхождение иллюстрации первого экрана описаны в `DESIGN.md`.
